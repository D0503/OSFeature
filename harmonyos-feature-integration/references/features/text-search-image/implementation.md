# 接入与资产

1. 扫描目标 product、承载 HAP、现有搜索和图片数据的入口，记录[回退基线](README.md#回退基线)。复用已有的文件、数据与结果展示逻辑。
2. 由业务生命周期管理同一进程中唯一的服务所有者。页面独占时可在 `aboutToAppear` 初始化、`aboutToDisappear` 释放。共享页面时由共享所有者收口，最后一个消费者离开后释放。运行门禁覆盖初始化、操作及清理；只有 `init()` 返回 `true` 后才提交其他操作。
3. 根据应用图片数据，对每个可读的沙箱路径调用 `insertImage(path, scope)` 建索引。逐项等待，分别记录成功与失败。使用同一作用域查询，按业务需要对结果副本按 `similarity` 降序排列。结果回填前核对请求仍与当前页面、查询和作用域一致，文件缺失沿用原图片加载策略。
4. 图片移除时按需要用原路径和作用域调用 `deleteImage` 移除索引记录，原文件管理沿用业务逻辑。生命周期退出时停止提交查询、使旧请求失效、等待已提交操作收尾后调用 `release`。释放失败由服务所有者保留状态并处理重试。重新进入、重复入库和重复删除的实际表现需真机验证。

## 输入与作用域

| 字段 | 约束 |
|---|---|
| `imagePath` | 应用内实际存在、可读的沙箱路径，长度 1–128。外部媒体 URI 如需入库，先按现有授权复制到沙箱，并保证路径在查询结果使用期间有效。图像宽高各须大于 100px 且小于 10000px。高宽比例建议低于 10:1。 |
| `scope` | 1–32 个字母或数字。按 API 参数表采用英文字母与数字组合，例如 `Album1`。按实际图库或业务分组固定映射，写入、查询与删除使用同一值。 |
| `query` | 1–100 字符，支持中文及混合数字、字母或符号。按参数表限制纯数字和纯字母，验证时用 `海边日落` 等中文描述。 |
| `topKey` | 可选整数，范围 0–100，默认 100，决定结果数量上限。 |
| `ImageObject` | 只读的 `imagePath`、`scope` 和 `similarity`。相似度范围为 [-1, 1]，越大越相似。官方未承诺返回顺序或固定分数阈值。 |

## Picker 选图入库

1. 复用现有选图流程。需要从系统图库选图时，用 [PhotoViewPicker](https://developer.huawei.com/consumer/cn/doc/doccenter-references/api/arkts-apis-photoaccesshelper-photoviewpicker) 的 `select()`，设置 `MIMEType` 为 `IMAGE_TYPE`，单图将 `maxSelectNumber` 设为 `1`，从 `result.photoUris` 取图。用户取消或未选中图片时直接结束。
2. 将选中的 URI 原样传给 `fileIo.open(uri, fileIo.OpenMode.READ_ONLY)`，用文件描述符将图片复制到应用沙箱。使用唯一的短文件名，关闭文件句柄，导入失败时清理本次临时文件。
3. 用 `ImageSource.getImageInfo()` 核对实际待入库图片的宽高，读取后释放 `ImageSource`。按[输入与作用域](#输入与作用域)校验沙箱路径和图片尺寸，随后以业务对应的 `scope` 逐张调用 `insertImage`。涉及转码时，以转码后的实际文件核验。

## 保存入库状态与恢复

应用需要跨重启保留图库时，可在现有数据仓库保存业务图片标识、沙箱路径、`scope` 和入库状态。提交 Kit 前先保存待入库记录，收到 `true` 后标记已入库。返回 `false` 或抛出异常时，记录失败原因并按业务保留重试入口。若本地记录写入失败，清理本次导入且未被引用的沙箱副本。

启动后在服务就绪时检查待入库记录和文件可读性，再串行恢复。若上次在 Kit 返回成功和状态落盘之间中断，同一路径可能已入库。按目标版本验证过的重复入库或索引核对策略处理该记录，避免仅凭本地状态确认能检索。遇到 `1013100003` 时进入全库重建流程。

## 模型更新与全库重建

`insertImage` 或 `search` 抛出 `1013100003` 时，暂停文搜图操作并保留原业务。用应用保存的源数据盘点同一文搜图数据库下所有待重建的作用域与可读图片。仅在清除范围已授权且有可恢复来源时，由统一所有者串行调用 `clearData()`。该方法清除整个文搜图数据库，没有作用域参数。

仅在清除返回 `true` 后逐项重新入库。记录各作用域重建进度和失败项，按业务恢复条件开放查询，再重试原请求。清除失败、重建中断或源不可用时显示现有故障反馈并保留可恢复状态。日常删除、释放和一般服务异常使用各自流程。

## 代码资产

优先复用工程已有的服务封装。需要补齐版本守卫、串行调用和生命周期管理时，可复用 [TextSearchImageSession.ets](assets/TextSearchImageSession.ets)。业务入口共享同一实例，业务层负责输入校验、路径管理和结果回填。

- `open` 对不具备运行门槛或返回 `false` 的初始化返回 `false`。就绪后可使用 `insert`、`search` 与 `remove`。
- `insert`、`remove`、`clearAllIndexes` 与 `close` 将 Kit 的布尔结果传回调用方。SDK 抛错时保留原异常，业务层按[错误码](validation.md#故障排查)处理。未就绪的读写操作抛出会话状态错误。
- `clearAllIndexes` 供已授权的全库维护调用。若接入范围只涉及查询或单图操作，工程入口只调用对应方法。
