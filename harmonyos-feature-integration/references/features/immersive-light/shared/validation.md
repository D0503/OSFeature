# 沉浸光感共享性能、降级与验证

本文件只维护 HDS 与 ArkUI 共用规则。选中路线后继续读取对应 `routes/<route>/validation.md`，组合路线两份都读。

## 共享降级要求

所有回退条件都以[接入前源程序状态](fallback.md)为基线。普通背景、边框或阴影只是视觉维度，不能替代组件树、布局、状态、数据、交互、生命周期和异常路径。

- API、设备能力或系统状态不满足时，不把材质作为业务状态的唯一表达；
- Web 同层渲染出现透明等异常时，关闭目标控件材质或相关同层能力，并保留源行为；
- 一个路线回退不自动禁止另一个已满足条件的路线；
- 任何新增尾部留白、布局偏移和应用配置都只进入需要它的增强分支。

## 悬浮 Tab 栏宽与断点

- HDS 与 ArkUI 沉浸光感接入分支删除外层 `.barWidth(...)`，由 `barFloatingStyle.barWidth` 的配置或默认行为自动生效，不额外添加固定宽度。内容容器宽度和 MiniBar 布局单独处理。
- 所有断点、横竖屏和窗口尺寸均使用底部横向 Tab：`vertical(false)`、`BarPosition.End`。移除该分支的侧栏切换条件及专属布局配置，保留控制器、页签状态和业务事件。
- 仅低版本兼容分支保留接入前的侧边/底部响应式布局及栏宽。设备不支持或材质关闭时使用材质回退，仍保持底部 Tab，不恢复侧栏。
- 静态扫描外层栏宽、方向与位置条件仅提供候选证据；需核对组件和版本分支及封装调用，不能因同文件存在旧版栏宽或侧栏就判定失败，也不能因存在 `vertical(false)` 就判定所有断点通过。
- 验证小/中/大断点、横竖屏、分屏和自由窗口下的底部栏位置、默认或自定义悬浮宽度、页签文字与内容容器；另在低版本验证原响应式行为。材质关闭与设备不支持时仍验证底部布局。

## 共享性能红线

1. 不给整页或超大背景设置材质，优先限制在卡片、工具栏、悬浮按钮等局部区域。
2. 不在父子节点重复嵌套材质，不给大量列表项分别设置材质。
3. 不叠加重复背景模糊、背景效果和多重阴影。
4. 不把材质覆盖在视频、动图等持续变化内容上。
5. 避免持续修改材质区域尺寸、位置、透明度、参数或子树结构。
6. 避免无限循环动画，控制 Dialog/Menu 的材质面积。
7. 不在大量文本和图标的整棵子树上开启自动反色。

## 共享测试矩阵

- 工程最低支持版本、API 23 和 API 26 中与选中路线有关的节点；
- 高、中、低算力设备；
- 系统沉浸光感“强、均衡、弱”档位；
- 深色和浅色模式；
- 材质支持、不支持、关闭三类结果；
- 动态背景、滚动内容、弹窗和持续动画场景；
- 接入前源程序回退路径；
- 组合路线中 HDS、ArkUI 各自成功以及单边回退的组合。

## 窗口沉浸状态与栏间距

Tab 页面需要同时延伸顶部和底部系统安全区时，提醒用户使用 HDS 底部 Tab：已反馈 ArkUI Tabs 在 `barBottomMargin: 0` 与 `.expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.BOTTOM, SafeAreaEdge.TOP])` 组合下，仍在底部系统导航区之上额外抬高 28vp。选路时说明该现象；用户保留 ArkUI 时，在目标设备核验实际栏位置，不能仅凭 margin 为 0 判定正确。

组件默认值不同：HDS 的 `barBottomMargin` 默认为 0，ArkUI Tabs 默认为 28vp。接到悬浮 Tab 开发需求后，先追踪目标窗口的 `setWindowLayoutFullScreen` 调用及其封装、初始化顺序、条件和后续关闭操作，再按下表实施；不限定窗口变量必须叫 `windowClass`。

| 已确认的目标窗口状态 | 接入方式 | 两条路线的 barBottomMargin |
|---|---|---|
| 已开启窗口沉浸式 | 复用现有窗口沉浸方案 | 显式设置 28vp |
| 未开启窗口沉浸式 | 每个 Tab 一级页均扩展底部系统安全区，不能只处理首页或当前选中页 | 显式设置 0vp |
| 调用链或生效状态不明确 | 先核对初始化、参数与实际窗口状态 | 不凭扫描结果选择分支 |

未开启窗口沉浸式时不为悬浮 Tab 或标题栏沉浸光感自动开启全局窗口沉浸式，改用安全区扩展让布局延伸到对应系统区下方：仅接入悬浮 Tab 时使用 `.expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.BOTTOM])`；接入标题栏沉浸光感时使用 `.expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.TOP])`；同一组件同时承担两种场景时一次调用 `.expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.BOTTOM, SafeAreaEdge.TOP])`，不拆成两次调用，避免第二次覆盖第一次的边配置。合并时保留组件已有且仍有效的安全区类型和方向。已开启窗口沉浸式的窗口复用现有沉浸方案，不因本次接入重复添加安全区扩展。

两条扩展链都逐组件配置，仅给末端容器设置属性不足以完成整条链的扩展。底部扩展逐个检查所有一级 Tab 页，沿主页面容器 → Tabs/HdsTabs → TabContent → 自定义页面根容器 → 真实滚动容器追踪，为滚动容器及其所有父组件配置扩展属性；顶部扩展逐个检查所有接入标题栏沉浸光感的页面，沿主页面容器 → Navigation/HdsNavigation（或 NavDestination/HdsNavDestination）→ 页面根容器 → 真实滚动容器追踪，同样为滚动容器及其所有父组件配置扩展属性。例如 MainEntry 中的父容器、Tabs 和 TabContent，以及 HomePage 的根 Stack 和 Scroll 构成同一条布局链；标题栏沉浸光感与悬浮 Tab 共存于同一条链时，链上共用组件按合并写法一次传入两边，仅处于单侧链上的组件只配置对应方向。

标题栏接入还需检查滚动容器内部的首项及背景绘制节点，不能只检查到 Scroll/List。例如 `Scroll → scrollContent() → Stack → Image(banner)`，若首屏背景图片需铺到状态栏下方而尚未覆盖，应继续逐组件核对内部布局链，并为需要延伸的节点配置 TOP 扩展；同一节点确有底部延伸需求时再合并 BOTTOM。首项并非一律扩展，文本、按钮等可操作内容仍需保留顶部避让，验证首屏及滚动时背景连续、内容可见且可操作。

扩展只作用于需要它的沉浸光感分支；共用容器、Builder 和复用页面按实际布局状态传递条件，普通 Tab、普通标题栏和独立页面保持原行为。不能把扩展无条件放进两个分支共用的根容器或内部背景节点。未接入标题栏沉浸光感的页面，顶部避让继续按工程原规则处理；接入标题栏沉浸光感的页面按上述 TOP 扩展规则延伸到状态栏下方。验证每个一级 Tab 的内容延伸、栏位置、顶部遮挡、标题栏材质对状态栏区域的覆盖及分支和窗口模式切换。

静态扫描仅收集窗口调用和安全区扩展候选：注释中的调用不算，`true`、`false`、参数封装和条件调用需核对实际调用链；未发现字面量 `true` 不等于未开启。出现扩展属性也不证明全部父组件已覆盖，TOP 与 BOTTOM 方向同理，需分别核对各自布局链。该项保持 `warn`，结合代码层级和实际页面验证，不以扫描命中替代生效结论。

未开启窗口沉浸式时，HDS、ArkUI 均须按全部 Tab 页清单逐页配置并切换验证，包括非默认页和懒加载页。**必须从真实滚动容器逐个向上追踪到页面宿主，为该扩展链上的每一个父布局组件配置对应方向的 `expandSafeArea`，不能跳过任何中间层级。**遇到自定义组件或 Builder，必须进入内部检查实际布局节点；仅配置 Scroll/List、页面根容器或公共 Tabs/HdsTabs 均不算完成。无滚动容器的页面也需逐父组件覆盖内容布局链；需要顶部延伸的页面同时按上述规则处理 TOP。不能以首页效果正常代替其他 Tab 页的配置与验证。

`HdsTabs`、ArkUI `Tabs` 及链上的 `TabContent` 本身也必须按需配置 `.expandSafeArea([SafeAreaType.SYSTEM], [...])`，不能只配置其父容器或内部页面。仅需底部延伸时传入 `[SafeAreaEdge.BOTTOM]`，仅需顶部时传入 `[SafeAreaEdge.TOP]`，同时需要两侧时一次传入 `[SafeAreaEdge.BOTTOM, SafeAreaEdge.TOP]`；配置仍限定在实际需要扩展的布局分支。

## 标题栏内容避让与自定义标题

HDS、ArkUI 标题栏改造后，先检查首个内容及操作热区是否被标题栏覆盖。需要避让时，按实际标题栏占用高度设置滚动内容起始偏移（如 `contentStartOffset`）或内容内部顶部 padding，复用已有避让，不重复叠加标题高度和系统安全区。不要用页面外层 padding 缩短整个滚动视口；需要透底的背景仍可延伸到标题栏下方，可操作内容单独避让。

自定义标题 Builder 必须明确高度：ArkUI 在 `.title({ builder: this.titleBuilder, height: this.titleHeight }, options)` 中声明，并使 Builder 根容器高度与之匹配；HDS 按对应标题栏接口核对自定义内容占用高度。高度由工程布局决定，不固定套用示例值；存在折叠或滚动联动时，分别核对初始内容偏移与当前标题高度，验证首屏、滚动、回顶及字体放大时无重叠或多余空白。

**改造沉浸光感标题栏时，默认要为标题栏中的按钮接入沉浸光感。**逐个检查返回、菜单及自定义操作按钮，按受支持的入口和生效域落实材质；自定义 Builder 必须进入内部，将配置落到实际按钮上，不直接给整个 `titleBuilder` 根容器铺设材质来代替按钮接入。系统返回键及非自定义菜单使用对应路线的标题栏材质入口；Search、选择类等其他组件按各自规则处理。标题栏滚动模糊与按钮材质分别配置、分别验证，不能仅有滚动模糊就视为按钮已接入。

## 普通与悬浮 Tab 的外层避让

HDS 与 ArkUI 接入前均须追踪原有 bottom padding 的用途和所属分支。普通 Tab 为避让导航条设置的外层 padding 仅保留在普通分支；悬浮分支由栏底部间距负责避让，页面内容和滚动视口继续延伸到栏下方。共用父容器时，将该 padding 按工程实际悬浮布局条件分支设置，不以材质开关代替布局判断。

同时存在悬浮 Tab 和 bottom padding 只构成静态核对线索，不能证明二者存在祖先关系或在同一分支生效。显式与默认栏间距都要检查，无法确定时保留 `warn`；不得机械清零 `barBottomMargin`，也不得删除其他布局用途的 padding 或列表内部的尾部补偿。验收时切换普通/悬浮分支及窗口模式，确认普通导航条避让正常，悬浮栏下方没有共用 padding 造成的固定空白。

## 悬浮 Tab 的滚动尾部避让

修改前必须逐页确认并记录：宿主到真实滚动容器的组件路径、当前窗口模式下的 `scrollable` 与嵌套滚动职责、已有 `contentEndOffset`/内容 padding/占位及其用途、最终由哪一个滚动容器承担本次补偿。未查清子组件实现时不得直接在宿主页追加占位；同一遮挡补偿只在实际负责该段滚动内容的容器中计算一次。

禁止在使用 `layoutWeight` 或填满剩余高度的 List/Tabs 外部、作为其兄弟节点追加固定高度 Blank 来避让悬浮栏。这会挤占列表视口，让悬浮栏下方变成固定空白。外层即使名为 Scroll，若其 `scrollable` 为 None、实际由内部 List 滚动，也不能在该外层内容末尾追加 Blank 代替内部列表补偿。内层已设置补偿时，不能再次在外层叠加；窗口模式改变滚动职责时分别判断，不能无条件同时补偿内外两层。

优先更新真实滚动容器已有的尾部配置，保留原间距语义。只有确认 Scroll 实际承担该内容滚动、尾部空间随同一内容滚动且不会缩小子列表视口时，才允许使用其内容末尾的 padding 或占位。

该规则同时适用于 HDS `HdsTabs` 和 ArkUI 原生 `Tabs`：只要悬浮栏通过 `barOverlap(true)` 覆盖内容，就逐个检查每个 Tab 页中的 `List`、`Scroll`、`WaterFlow`、可滚动 `Grid` 和自定义滚动容器。最后一个可操作项及其点击、拖拽或手势热区必须能够完整滚动到悬浮栏上方。

- 先沿页面、TabContent 和自定义子组件追踪真实滚动容器，检查 `scrollable`、嵌套滚动及窗口模式。外层 `Scroll` 为 `ScrollDirection.None`、内部列表负责滚动时，补偿应落在内部列表；窗口模式改变滚动职责时重新核对，不能仅凭存在 `Scroll` 就在外层加 padding。
- 保持页面内容和滚动视口延伸到悬浮 Tab 下方。不得通过页面根容器、列表外层容器的 bottom padding 缩短内容区来避让，否则悬浮栏下方会露出固定预留空白，失去正常页面背景。
- 在最后一个真实滚动项之后增加尾部空间，默认遮挡补偿为 `barHeight + barBottomMargin`，使用最终实际配置的栏间距；未设置时 HDS 默认 0、ArkUI Tabs 默认 28vp，再结合必要的操作间隔；外层已经承担的系统安全区不要重复加入；
- `List` 可使用 `contentEndOffset` 或尾部占位项；只有外层 `Scroll` 确实负责该内容滚动时，才在其内容 `Column` 末尾增加 `Blank`等价空间；
- 已有 `contentEndOffset` 或内容间距时，保留原间距语义并计算新增遮挡补偿，避免直接覆盖或重复叠加。宿主根据当前页面实际存在的悬浮栏遮挡确定补偿，再传给真实滚动组件；独立页面或无悬浮栏的复用场景保持原间距。
- 尾部空间只负责滚动内容防遮挡，不替代决定悬浮栏位置的外层 padding、系统安全区或栏外边距；同一段安全区高度不得重复计算；
- 仅在实际渲染为悬浮重叠布局的分支启用补偿。低版本、设备不支持或业务关闭材质的路径如果已经恢复为普通非悬浮 Tabs，则继续保留接入前的滚动范围和 padding；如果仍使用 `barOverlap(true)` 的普通样式悬浮栏，仍需尾部避让；
- 无滚动内容的 Tab 页不增加空白；所有 Tab 页逐页验证，不能只检查默认页。

静态扫描发现 `contentEndOffset` 或 `Blank` 只表示存在候选，不能证明其属于目标列表、位于内容末尾或高度足够；页面级 padding 也不能作为滚动尾部避让的通过证据。无法确认每个实际滚动容器及其补偿值时，保持 `warn`，逐项核对组件层级与运行效果。

## 共享验收标准

- 对每个一级 Tab 及其内部可切换列表，实际执行开始滚动、持续滚动、滚到末尾和末项操作：过程中真实内容应经过悬浮栏下方，末项能完整滚出遮挡；尾部空间仅随内容进入视口，不形成固定底部空带；
- 实施记录已明确各窗口模式的真实滚动容器与唯一补偿位置，已排除列表外固定占位和内外重复补偿。仅有静态 `warn`、编译通过或默认页截图不能完成该项验收；未执行逐页滚动时报告未验证，观察到固定空白或重复补偿时报告失败并修复后复验；
- 接入标题栏沉浸光感的页面，逐页验证安全区扩展覆盖整条父组件链：标题栏材质延伸覆盖状态栏区域，内容不被状态栏遮挡，未接入页面的顶部避让保持原行为；悬浮 Tab 与标题栏共存的链路上核对合并写法一次传入两边，不出现两次调用相互覆盖；

- 本机 SDK、工程 API、Stage/module 和设备上下文有文件证据；
- `selectedRoutes` 与工程真实组件体系一致；
- 每条选中路线只使用自己的接口、门禁和资料；
- 旧版本、不支持、禁用或外部条件不满足时保留接入前源程序状态；
- HDS 或 ArkUI 悬浮 Tabs 的每个可滚动页面都能让最后一个可操作项完整滚到悬浮栏上方；
- 滚动过程中页面内容能正常经过悬浮栏下方，视口没有被外层 padding 提前截断；到达末尾时允许内容尾部补偿随滚动进入视口，不将它误判为页面固定空白；
- 没有明显的大面积、嵌套、动态背景或无限动画风险；
- 静态检查、真实构建、真机验证和未完成项分层报告；
- 组合路线分别给出结果，不以一条路线的成功替代另一条。
