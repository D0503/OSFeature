## 共享测试矩阵

- 工程最低支持版本、API 23 和 API 26 中与选中路线有关的节点；compatible 低于路线门槛时，最低支持版本节点必须实测回退表现并以 `fallback` 判定补录（见[回退路径的实测验证](fallback.md#回退路径的实测验证)）；
- 高、中、低算力设备；
- 系统沉浸光感“强、均衡、弱”档位；
- 深色和浅色模式；
- 材质支持、不支持、关闭三类结果；
- 动态背景、滚动内容、弹窗和持续动画场景；
- 接入前源程序回退路径；
- 组合路线中 HDS、ArkUI 各自成功以及单边回退的组合。

## 窗口沉浸状态与栏间距

涉及标题栏或悬浮 Tab 的安全区、窗口沉浸状态或栏间距时，按知识库查询流程读取《沉浸光感悬浮 Tab 布局与避让》，定位「窗口沉浸状态与栏间距」。已读取同篇时直接复用正文。

静态扫描仅收集窗口调用和安全区扩展候选。排除注释，核对实际调用链中的参数、条件、封装和生效顺序。按 TOP 和 BOTTOM 分别核对整条布局链。静态证据不足时保留 `warn`，结合实际页面验证。

## 普通与悬浮 Tab 的外层避让

按[共用布局知识查询](#窗口沉浸状态与栏间距)读取《沉浸光感悬浮 Tab 布局与避让》的「普通与悬浮 Tab 的外层避让」。

## 悬浮 Tab 的滚动尾部避让

按[共用布局知识查询](#窗口沉浸状态与栏间距)读取《沉浸光感悬浮 Tab 布局与避让》的「悬浮 Tab 的滚动尾部避让」，核对真实滚动容器、补偿位置、实际遮挡和布局分支。

静态扫描发现 `contentEndOffset` 或 `Blank` 只表示存在候选，不能证明其属于目标列表、位于内容末尾或高度足够。页面级 padding 也不能作为滚动尾部避让的通过证据。无法确认每个实际滚动容器及其补偿值时，保持 `warn`，逐项核对组件层级与运行效果。

## 共享验收标准

涉及标题栏安全区或悬浮 Tab 布局时，复用已读的《沉浸光感悬浮 Tab 布局与避让》中的「布局验收标准」。单独验收时按[共用布局知识查询](#窗口沉浸状态与栏间距)取得正文，再执行以下检查。

- 对每个一级 Tab 及其内部可切换列表，实际执行开始滚动、持续滚动、滚到末尾和末项操作：过程中真实内容应经过悬浮栏下方，末项能完整滚出遮挡；尾部空间仅随内容进入视口，不形成固定底部空带；
- 实施记录已明确各窗口模式的真实滚动容器与唯一补偿位置，已排除列表外固定占位和内外重复补偿。仅有静态 `warn`、编译通过或默认页截图不能完成该项验收；未执行逐页滚动时报告未验证，观察到固定空白或重复补偿时报告失败并修复后复验；
- 接入标题栏沉浸光感的页面，逐页验证安全区扩展覆盖整条父组件链：标题栏材质延伸覆盖状态栏区域，内容不被状态栏遮挡，未接入页面的顶部避让保持原行为；悬浮 Tab 与标题栏共存的链路上核对合并写法一次传入两边，不出现两次调用相互覆盖；

- 本机 SDK、工程 API、Stage/module 和设备上下文有文件证据；
- `selectedRoutes` 与工程真实组件体系一致；
- 每条选中路线只使用自己的接口、门禁和资料；
- 旧版本、不支持、禁用或外部条件不满足时保留接入前源程序状态；
- HDS 或 ArkUI 悬浮 Tabs 的每个可滚动页面都能让最后一个可操作项完整滚到悬浮栏上方；
- 滚动过程中页面内容能正常经过悬浮栏下方，视口没有被外层 padding 提前截断；到达末尾时允许内容尾部补偿随滚动进入视口，不将它误判为页面固定空白；
- 没有明显的大面积、嵌套、动态背景或无限动画风险；
- 静态检查、真实构建、真机验证和未完成项分层报告；
- 组合路线分别给出结果，不以一条路线的成功替代另一条。

## 工程整体接入覆盖

整体接入沉浸光感时，逐实例清单是覆盖核对依据。默认开启组件也需导航到实际页面或触发弹窗、菜单、Toast 后验证；不能用首页截图或全局 ENABLE 代替其他组件证据。所有候选均有处理结论才算完成盘点，仍待核对或未验证时明确覆盖限制，不宣称全量效果通过。

在最终报告的“改造汇总”中简要列出覆盖情况：组件类别、已盘点位置、处理结论、未覆盖原因。已实际改造项沿用逐项结果；默认开启无需修改、不适用和待核对项也说明去向，不伪造修改文件。详细工作清单留在临时目录，最终仍只交付原 Markdown 报告及引用截图。

### 工程发现

沉浸光感需区分“指定组件接入”和“工程整体接入”。指定组件只处理授权范围；整体接入读取 `materialInventory` 的完整候选位置，并对照 ArkUI 组件矩阵及 HDS 组件范围逐项盘点，不能只处理底部 Tab。
候选发现不依赖 `systemMaterial`，包含组件调用、Popup/Tips/Sheet/Menu 绑定入口、Toast/Dialog 方法及 Options 引用。`signals` 的位置证据有数量上限，不能代替 `materialInventory.candidates`。配置类型引用只是线索，须关联实际调用并合并同一实例；继承类型、命名空间别名、动态调用和业务封装继续人工追踪。`unresolvedEntrypoints` 中的 PromptAction、原生接口线索必须核对其实际方法和版本，不套用 ArkTS Options。
对扫描未命中的矩阵类别也检查项目封装、导入别名与调用入口；确认未使用后记录“未发现实际使用”，无法确定则记录“待核对”，不能把正则未命中等同于不存在。普通内容区 Button 等仍列为候选，核对生效区域后决定是否不适用，不自动添加材质。
在执行期间维护逐实例清单：页面、文件与行号、组件/接口、宿主层级、版本分支、应用状态、默认开启条件、背景等属性、处理结论、验证状态及证据。处理结论使用“默认开启无需新增配置 / 需要显式接入 / 冲突需处理 / 不支持或区域不适用 / 待核对”。这一清单放在临时执行记录中，不新增交付文件。

模块扫描同时保留原始 `applicationMaterialState`，并输出规范化的 `effectiveApplicationMaterialState`；未配置时为 `default`，非法值为 `invalid`。

### 整体接入方案

工程整体接入沉浸光感时，以逐实例盘点清单说明每类候选的处理范围；默认开启不等于已验证，需显式接入的组件不能由应用级 ENABLE 替代。未支持的区域或类型保留原行为并说明原因，不为了覆盖率增加无效材质。

### 整体接入复核

整体接入沉浸光感时，重新扫描并与实施前逐实例清单核对，补齐新增、遗漏或封装内的实际调用。所有范围内候选都必须有处理结论，待核对项明确保留；不能仅完成 Tabs 与滚动避让、配置应用级 ENABLE 就宣布工程整体接入完成。无需改代码的默认开启组件也必须验证，不强制重复显式配置。
