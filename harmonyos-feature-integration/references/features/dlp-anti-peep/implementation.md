# 接入实施

扫描实际宿主、敏感内容范围、窗口所有者与既有保护行为。按用户目标选择 [状态感知](routes/status-observation.md) 或与 [系统蒙层](routes/system-mask.md) 组合；常规系统蒙层方案同时使用两条路线。

完成 [权限与版本](compatibility.md) 后接入当前状态读取和事件；只把确定的 PASS/HIDE 传递给业务，失败是 unknown。复用已有业务的保护策略，不自行新增隐藏字段、弹窗或页面。

所有者应覆盖受保护窗口的可见生命周期。每个所有者保存同一回调、成功订阅标志和异步代次；退出时先使代次与目标ID失效，再退订本次回调。重新可见时重查开关/状态，不沿用过时查询。全局窗仍展示时不能因主页面隐藏而机械取消其所有者。

对每次新的 HIDE 状态及窗口目标变化尝试保护，合并并发通知；蒙层成功前不报告 protected。恢复 PASS 时不调用放通接口，不伪造不存在的取消蒙层 API。系统蒙层交互由系统管理，按实测验收。

仅当用户明确选择放通时调用 passDlpAntiPeepInfo；该状态持续到锁屏或应用退出，不能用作初始化、异常回退或自动关闭蒙层。仅需结束监听时 off 即可。publishAntiPeepInformation 只按明确业务需求启用，避免重复提醒。
