# 原程序回退

基线为 `pre-integration-source-state`。隔空传送不可用时保留接入前的页面、响应式布局、横竖屏与窗口适配、导航、数据、播放、事件和已有分享入口，不重置业务状态。

## 条件与处理

| 条件 | 回退行为 |
|---|---|
| 运行版本低于接口门槛 | 不执行不支持的隔空调用；API20 事件的注册和退订均受版本保护，继续原业务和原分享入口 |
| SysCap 不支持或型号无手势能力 | 不启用对应增强，保持原页面和操作；不能仅凭 SysCap 代替具体型号的手势实测 |
| 系统隔空传送关闭 | 保持原业务；不因无回调推断注册失败，不编造开关查询或切换接口 |
| 用户拒绝信任或取消传送 | 尊重系统处理结果，不自动确认、不重复发起，也不切换其他分享方式 |
| 窗口获取或注册失败、窗口无效 | 处理异常，停止本次接入尝试，原页面与分享操作继续可用；失败不报告已注册或已发送 |
| 空选择或内容未准备 | 不发送旧内容、不构造空 SharedData；已收到分享回调但无内容时使用 reject(NO_CONTENT_ERROR) 并处理拒绝结果，下载等准备工作在回调前完成 |
| share 同步异常或 Promise 拒绝 | 沿用已有失败反馈，不自动拉起系统分享面板、不新增按钮或提示，不更改原业务结果 |

已有独立操作入口按原业务保留；接入没有新增入口时，不增加隐藏入口或 Toast 的选择流程。版本保护的范围检查见[扫描与回退](compatibility-audit.md)。

页面隐藏、退后台和销毁属于正常生命周期清理：仅退订本页面拥有的窗口和实际回调，恢复时沿用已有可见生命周期重新注册。退订失败记录异常，不能声称清理成功；异步窗口返回时按工程已有状态确认页面仍可分享，不要求引入专用状态字段。

App Linking 与隔空事件独立判断。低于 API20 但仍支持原有链接能力的环境，保留已有链接接收、统一冷暖启动处理入口及业务路由。域名未关联、元服务链接未生效或过期、未安装应用及内容不存在按[链接配置](app-linking.md)和原业务处理；不能将 Web 页面出现判为应用或元服务内容直达成功。

## 回退路径的实测验证

按[通用回退实测](../../workflows/verification.md#回退路径实测)取证与补录，并对照[隔空传送验证方案](performance-validation.md)检查以下场景：

- 工程 compatible API 低于20时，在不低于 compatible、低于20的环境安装本轮构建产物，验证不执行隔空事件注册及退订，无报错崩溃，原页面、布局、状态、已有分享入口和受支持的业务仍正常。按 `low-api` 补录回退环境与证据。
- compatible 已达到20时，`low-api` 标为不适用并说明依据；在最低受支持版本和较高版本验证，不要求安装到工程不支持的系统。
- 能力不支持与系统关闭分别在实际可触发的环境验证原业务保持，按 `unsupported`、`disabled` 分别补录。SysCap 不支持、型号不支持与系统关闭不能用同一现象直接推导；窗口失败、空内容、信任拒绝、取消和分享失败作为对应负向运行场景分别记录结果。
- API20 门槛下的回退验证关注“增强不调用、原业务保持”，不依赖隔空识别硬件；低版本模拟器只能证明该环境的回退表现，不能证明双端手势传送。高版本抓取和接收效果仍按能力包的双端真机要求另行验证。
- 对照接入前基线检查组件树、断点与窗口布局、数据和播放状态、事件与生命周期、导航及已有分享行为。采用 App Linking 时另验证其独立的可用与失败路径。

使用同一轮构建产物验证，回退截图按通用流程标记用途。缺少设备或无法触发对应条件时写明未验证及具体阻断；静态复核、异常注入和构建通过不能替代真实低版本运行证据。
