# 隔空传送扫描与回退

按[共享工作流](../../workflows/compatibility-audit.md)核对各 product 的最低兼容版本与实际 SDK `@since`，覆盖 `gesturesShare` 的 on/off 重载、回调中的 share/reject、数据构造、初始化及退出清理。沿导入、别名和页面/VM 封装复核；普通手势、`knockShare` 或系统分享面板不作为隔空传送接入证据。

`gesturesShare` 事件从 API20 起，不能用 `SharableTarget` 或其他分享重载的较早版本降低门槛。compatible 低于20时，版本保护必须先于不支持的调用，包括退出时的 off；SysCap 不代替版本保护。compatible 已覆盖某接口门槛时，无需额外增加该版本分支，仍检查设备能力与生命周期。版本判断方式遵循[兼容性模型](../../shared/compatibility-model.md)，已有等价有效守卫直接复用。

版本或能力不满足时不注册、不调用对应隔空接口，保留原页面、业务数据和已有分享入口。系统关闭、信任拒绝、窗口获取失败或传送失败按[回退规则](fallback.md)处理，不自动拉起其他分享方式、不新增替代入口。未新增独立操作入口时，保留已有业务即可，不套用其他特性的隐藏入口或 Toast 选择流程。

注册与退订须属于同一目标窗口和实际回调；页面隐藏、退后台及销毁时清理自身订阅，恢复时只注册当前可分享页面。异步获取窗口的工程复用已有可见状态，确认返回时页面仍可分享；不能为清理调用绕过版本保护。

App Linking 按实际用到的接口独立判断。隔空传送不可用时，仍保留已受支持的链接接收、统一冷暖启动入口及业务路由，不因 API20 隔空门槛删除原有链接能力。配置未完成或链接无效按其自身流程处理，不作为隔空事件的低版本回退结论。

高版本按[验证方案](performance-validation.md)使用双端真机验证抓取、传送与接收内容；低版本验证无不支持调用，原页面、分享入口与业务状态保持。关闭和失败场景分别验证，见[回退路径实测](fallback.md#回退路径的实测验证)。扫描与检查只报告，明确要求修复时才修改工程；缺设备时标记未验证，不以构建通过替代运行。
