# 验证与证据

## 静态和构建

运行 `verify-integration.mjs --feature gestures-share --route gestures-share`，复核所有 warn，不以候选匹配认定完成。确认 API20/Stage/普通应用、同窗口与同一实际回调的 on/off、前台可见范围、后台清理与恢复、当前业务数据、share/reject 的同步和 Promise 异常。选择链接直达时按接收目标复核[链接配置](app-linking.md)：应用检查域名 skill、手动签名及 Want.uri；元服务检查平台链接状态与有效期、动态 URI/静态 parameters 和主包/子包路由。两者均检查 onCreate/onNewWant 是否进入同一个链接处理入口，以及冷暖启动结果；后续状态传递和导航方式可沿用工程实现，不要求采用文档中的共享模型或监听 API。

按通用 `verify-development.mjs` 完成工程静态检查、SDK 检查、构建、完整产物部署、目标页导航和报告。构建通过不代表硬件、系统开关、信任或 App Linking 平台状态已通过。

## 双端真机验证

实施代理先按[手机设置指引](compatibility.md#系统设置和信任)向开发者展示具体开启路径和信任确认步骤，引导其在双端亮屏解锁、开启华为分享与隔空传送，并由本人完成“一抓一放”。记录双端型号、系统/API、真机身份、账号关系和应用版本，采集发送卡片、接收结果、带时间戳的 share 调用/结果日志及接收内容截图。日志不得包含令牌或私密正文。未具备双端真机时明确运行与视觉未验证，模拟器截图和手势模拟不算证据。

| 场景 | 验收内容 |
|---|---|
| 文件单选/多选 | 当前已选文件与接收端名称、类型、内容一致；空选择拒绝，URI可读，无过早删除 |
| 链接分享 | 标题、描述、封面和接收链接匹配当前内容 |
| 可选链接直达 | 应用验证域名关联、已安装冷暖启动和未安装 Web；元服务验证平台链接有效期、动态/静态参数、主包/子包冷暖启动及所选浏览器入口 |
| 切换内容 | 文章/视频/选择变化后再次抓取不能发送旧数据 |
| 生命周期 | 页面隐藏、缓存 Tab 切换、退后台、销毁均不继续提供业务数据；返回当前前台页后只注册一次 |
| 窗口作用域 | 注册与退订使用同一目标窗口和回调；若工程异步获取窗口，检查返回时目标页仍可分享 |
| 设置与信任 | 同账号、不同账号双端确认、拒绝/取消、信任到期及系统关闭路径如实记录 |
| 失败回退 | API<20、能力不支持、窗口失败、断网/内容未就绪、分享失败保留原业务和分享入口 |

本次业务选用文件或链接哪些场景，就验收哪些；不为测试擅自增加产品场景。共同生命周期与回退不能省略。传送开关关闭而截屏开关开启可能只截屏，不据此判通过。

回退条件、预期行为及低版本取证按[回退路径实测](fallback.md#回退路径的实测验证)执行，分别记录低版本、能力不支持、系统关闭和各负向运行场景，不能以传送未发生推断原业务回退正确。

## 性能与报告

记录从事件回调到调用 target.share 的耗时，目标为指南建议3秒内；分开记录 Promise 完成和接收端真实结果。提前下载/缓存数据，避免阻塞 UI；检查连续进出页面后的监听数量和内存，不重复注册。大文件在实际网络/设备上记录耗时和失败，不能承诺固定吞吐量。

人工补录运行/视觉 passed 时须写明双端真机、发送与接收证据及本次内容一致性。运行判定 observations 至少包含 `sender-grab`、`receiver-content`、`background-cleanup`，每项 note 说明双端设备、内容与实际结果，evidence 引用本轮 runtime.evidence 内日志/组件树的 id 与 sha256；视觉 passed 须引用发送与接收两张不同截图。接收端证据按通用手动证据路径导入，保留设备归属说明。选择链接直达时另附冷暖启动证据，以及应用域名关联或元服务平台链接状态、有效期与参数接收证据；只有发送卡片、截图保存提示或 share Promise 成功不能证明端到端直达。报告复用通用结构化记录，分别写明静态、构建、部署、导航、运行、视觉与回退的结果或具体阻断。

交付回复须展示[手机设置和真机操作步骤](compatibility.md#系统设置和信任)，包含具体开关路径及官网链接；选择链接直达时再展示[开发者配置指导](app-linking.md#接入完成后向开发者展示)，明确该手动签名要求属于 App Linking 链接直达。分别说明工程接入结果、开发者待设置或配置项与实际验证状态。
