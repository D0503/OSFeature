# 回退

低于所用接口 API、设备不支持、未获授权、系统禁用、后台启动失败或服务错误时，不创建/启动增强窗口，继续接入前的页面、导航、状态、数据和交互。仅清理本次拥有的控制器、监听和资源，不终止其他业务窗口。

绑定失败不改为并行显示或擅自改成独立模式；停止失败保留可恢复引用，依据状态回调收敛。不为不可用入口增加空白占位。回退只表示未启用能力，不声明功能验证成功。

## 回退路径的实测验证

回退行为不能只靠静态复核或构建通过认定。按[验证闭环](../../workflows/verification.md)执行顺序第 7 条：

- 工程 compatible API 低于所选路线门槛（float-view/binding 26、floating-ball 20）时，必须在低版本环境安装本轮构建产物实测：不创建/启动增强窗口、不残留悬浮入口或空白占位，接入前的页面、导航、状态、数据与交互保持，无报错崩溃；采集回退环境运行截图与日志，以 `--judgment` 的 `fallback` 字段（condition 填 `low-api`）补录，summary 写明回退环境与逐项核对结论。
- 未获 ACL 授权、系统禁用、后台启动失败或服务错误的回退按[兼容性](compatibility.md)的触发方式在达标环境实测，分别以 `unsupported`/`disabled` 补录；不能以“窗口未弹出”静态推断回退正确，须同时确认原入口与业务功能无损。
- 低版本回退实测验证“增强不启用、源基线保持”，不依赖闪控窗/球硬件能力，允许使用 API 达标的模拟器；窗、球及防窥联动的显示效果按能力包各自的设备条件另行验证。
- 无法获得低版本环境时报告保留未验证并写明具体阻断。
