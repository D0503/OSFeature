# 桌面快捷方式扫描与回退

适用于已经接入桌面快捷方式的工程：识别现有配置和接口在最低兼容版本上的风险，补齐版本保护与回退，保留高版本快捷方式功能和低版本原业务。按[公共兼容性工作流](../../workflows/compatibility-audit.md)核对各 product 的有效 `compatibleSdkVersion`、实际编译 SDK 与相关声明；不通过提高最低兼容版本解决问题，不重新选接入路线或补做未要求的功能。

## 已有接入与保护范围

从目标 UIAbility 的 `ohos.ability.shortcuts` metadata 追踪真实 profile，沿 AppGalleryKit、AbilityKit 或旧 shortcutManager 模块的导入、别名和业务封装定位实际调用。记录已使用的配置字段、接口、入口和业务目标；只对现有接入制定回退。扫描结果是候选，须继续核对实际接收者、重载和控制流。

将每个已用运行接口的[版本门槛](compatibility.md#版本矩阵)与对应 product 的最低兼容版本比较。最低版本已覆盖门槛时复用已有路径，无需额外添加该版本分支；最低版本低于门槛时，保护必须先于不支持的访问，包括页面初始化、预校验、按钮处理、异步回调及恢复时的重新调用。SysCap 与设备支持检查独立核对，不能代替版本判断。版本判断方式遵循[公共兼容性模型](../../shared/compatibility-model.md)，已有等价有效守卫直接复用。

## 按实际能力制定低版本回退

| 已接入能力 | 低版本回退 |
|---|---|
| API9 静态基础配置及 wants.parameters | 在工程支持的 Stage 系统上保留配置、参数接收与业务导航。其他可选接口不可用时，仍保留这条独立业务路径 |
| API14 动态预校验与加桌请求 | 低于14不调用两种 checkPinShortcutPermitted 重载及 requestNewPinShortcut，不生成或复用 tid；保留应用原有业务入口与操作 |
| API20 配置查询与显示隐藏 | 低于20不调用 getAllShortcutInfoForSelf、setShortcutVisibleForSelf；保留可用的静态入口及原有业务可见性规则 |
| API24 已加桌查询与删除 | 低于24不调用 getPinShortcutInfos、removePinShortcut；按原应用不可用策略处理管理操作，不用静态配置列表冒充桌面状态，不改写记录声称已删除 |
| API26 设备支持查询 | 低于26不调用 isShortcutSupported，沿用对应版本已有的设备与能力判断；不以无法查询推断支持或不支持，不连带关闭该版本可用的静态或动态功能 |

`visible` 是声明式配置字段，API20 起生效，直接配置并由系统处理低版本兼容；保留已有配置值。该字段不需要运行时版本守卫或分版本配置，也不参与路线 `requiredApi` 的计算。程序化查询及显示隐藏使用的运行接口仍按 API20 门槛分别保护。

回退优先复用工程已有处理。既有入口的隐藏、禁用或提示策略保持一致；需要改变用户可见的入口行为时先确认。动态加桌不可用时不自动改成另一条路线，也不新建替代页面或入口。各能力分别保护，不能用 API24/26 管理接口的较高门槛包住整个快捷方式功能。

## 保留业务与异常回退

保留已有快捷方式 ID、资源、Want 参数约定以及 onCreate/onNewWant 到业务页面的冷暖启动路径。已有桌面图标进入应用时，不能因当前系统不支持某个加桌或管理接口而阻断原路由、登录及鉴权流程。对照修复前的组件树、布局、状态、数据、事件和普通样式；缺少历史基线时记录未知，不反推接入前实现。

版本或设备能力不满足时停止对应快捷方式操作；已存在的普通业务继续运行。系统服务失败、用户拒绝、tid 过期或目标变化时，按[回退规则](fallback.md)保留原业务和真实状态，清理失效事务，不自动重试系统弹框。页面退出后返回的校验结果不能重新启用失效入口，不自动删除已加桌图标或重置业务数据。

## 回退验证

修复后复扫、构建，按[验证方案](performance-validation.md)覆盖高版本功能、最低兼容端和实际使用的各接口门槛之间的分支。低版本验证不支持的接口没有被调用、原业务及仍受支持的快捷方式可用；高版本验证原有加桌、查询或管理功能正常。已加桌图标的冷暖启动和普通应用启动均需验证。

测试系统不得低于工程 compatible；静态基础配置以 API9 Stage 为基线，不要求验证不受支持的更低系统。动态功能的运行与视觉验证遵循真机限制。缺少设备或相关版本时保留已完成的源码核验与具体阻断，不以构建通过代替回退运行结果。用户只要求扫描时报告各处保护及回退方案，明确要求修复时才修改目标工程。
