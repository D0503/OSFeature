# 回退与源程序状态

基线为 `pre-integration-source-state`。新能力只在已满足版本、设备及服务条件的分支执行。

- 系统版本不足、SysCap 不支持或非支持设备：不创建控制器、不构建 Function 组件、不调用查询及 on/off，继续原组件和业务路径。
- 入口是新增时：不可用分支不保留空白占位或额外边距；原布局不受影响。
- 入口替换已有业务操作时：仅在用户确认替换方式后实施，保留原操作的代码、数据、事件和导航路径，失败不改变原业务结果。
- 查询 false、账号/网络异常或服务不可用时：保留原路径与业务状态。隐私待授权单独处理，不能永久封死用户主动授权入口，详见[实施](implementation.md)。
- 页面消失或重新实例化：只取消本实例订阅，忽略迟到查询结果。回到页面可恢复查询，不重复打开对话框。

对照接入前后检查组件树、横竖屏及窗口布局、主题样式、原点击行为、焦点、状态/数据、控制器和生命周期。不要为不可用环境生成新的低配聊天页、替代智能体或新的账号登录流程。

## 回退路径的实测验证

回退行为不能只靠静态复核或构建通过认定。按[验证闭环](../../workflows/verification.md)执行顺序第 7 条：

- 工程 compatible API 低于 20（元服务及 ICON_ABOVE_TITLE 能力为 21）时，必须在低版本环境安装本轮构建产物实测：不创建控制器、不构建 Function 组件、不调用查询与 on/off，新增入口不留空白占位或额外边距，原组件与业务路径保持；采集回退环境运行截图与日志，以 `--judgment` 的 `fallback` 字段（condition 填 `low-api`）补录，summary 写明回退环境与逐项核对结论。
- “运行与视觉验证须 Phone/Tablet 真机”针对智能体拉起与对话框效果；低版本回退实测验证“组件不创建、原路径保持”，不触发智能体服务，允许使用 API 达标的模拟器。
- 查询 false、账号/网络异常、服务不可用、隐私未同意在达标真机上按[实施](implementation.md)触发方式实测，以 `unsupported`/`disabled` 补录。
- 无法获得低版本环境时报告保留未验证并写明具体阻断。
