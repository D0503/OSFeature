# 验证与验收

沿用通用验证闭环，唯一 route 为 `function-component`。

## 静态与构建

检查 SDK 根清单、compile、compatible、Stage、应用类型、实际承载 HAP；元服务及 ICON_ABOVE_TITLE 要求 API 21。核对必填参数、真实 agentId、controller 绑定、事件清理、初始化参数改变时重建、所有 API 调用与构造的版本保护、原程序回退。

扫描记录的是候选证据。动态配置、跨文件封装、控制流、回调身份、平台关联及签名身份无法由关键字证明，warn 项须结合源文件复核。所有参数是初始化项，不把赋值语句当作运行时更新成功证据。没有接入实例时不能通过实施验收。

执行具备条件的真实工程构建。无工程/SDK/签名时记录未验证，夹具和脚本测试不能冒充 ArkTS 编译或服务联调。

## 真机验证

只使用已确认的 Phone/Tablet 真机；模拟器不执行本特性的运行验收，设备类型未知时先确认。SDK 或构建通过不代表设备支持。

1. 确认 Agent、应用关联、手动签名身份、测试发布或正式发布、地区、登录、隐私与网络条件。
2. 进入目标页，检查图标/按钮布局、主题及大字体，截取入口状态。
3. 用户点击 Function 入口，确认打开的是目标 Agent，对话框正常显示，按钮 queryText 与确认的意图一致。截取打开状态，记录点击及打开的运行日志/交互证据。
4. 关闭对话框，确认返回原页面且原状态、业务操作仍可使用；记录关闭证据。事件订阅为可选，不为验收强制添加业务不需要的监听。
5. 页面往返及重复开关不发生重复订阅、重复打开、状态丢失；有动态参数场景时验证重建后使用新值，不接收旧查询结果。

运行通过需在判定文件 `runtime.observations` 中提供 `entry-clicked`、`dialog-opened`、`dialog-closed` 三项，每项含 `scenario`、`note` 与 `evidence`（本轮证据的 id/sha256）。这些字段用于确认 AI 已逐项阅读实际交互，不可按模板虚构。`runtime.evidence` 仍必须引用日志或交互组件树。视觉通过至少引用入口与打开状态两张截图；不能凭单张按钮截图宣称拉起成功。

## 负向场景

- 低版本、SysCap/设备不支持：仍可操作原页面，不触发不支持 API。
- 无效 ID、未关联应用、appid 不匹配：可诊断，原业务不丢失。
- 隐私未同意：有用户主动完成授权的恢复路径，不自动接受协议。
- 未登录、离线/弱网、内部错误：无无限重试；条件恢复后可重新操作。
- 元服务 API 20、ICON_ABOVE_TITLE API 20：必须被版本门禁拦截。
- 测试版本过期、白名单变更及正式/测试版本混淆：按平台指引核对。

不设置无依据的性能数值门槛；检查重复查询、监听泄漏、页面销毁后回写和阻塞 UI 等实际风险。最终报告区分静态、构建、真机运行和视觉结果，平台未就绪或缺真机时写未验证。
