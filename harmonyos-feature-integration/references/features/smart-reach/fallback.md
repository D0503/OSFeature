# 保留源程序状态

`fallbackPolicy.baseline: pre-integration-source-state`。降级只是不启用跟手增强；不新增一套简化页面，不改变原导航、事件、数据、主题或断点布局。

自定义握持感知区分明确关闭与暂时识别不到：明确关闭时恢复接入前位置；暂时识别不到时保持当前侧，没有收到过有效左右手状态则保持初始位置。原位置按当前断点、方向和窗口尺寸下的原布局确定，不固定为右侧，也不使用过期坐标。

采用“保留原组件，新增同步跟手组件”模式时，恢复源基线指撤去新增入口，原组件始终保留原位置和共享业务状态。低版本、不支持或首次订阅失败时不创建新增入口；收到首个有效方向前只展示原组件。新增入口已展示后暂时无识别结果，保持其当前侧；明确关闭或错误回退时撤去，不能同时删除原入口或重置已完成的业务结果。

| 条件 | 行为 |
|---|---|
| 低于所选路线 API | 不执行新 API/新属性链，继续原组件或原代码路径 |
| SysCap 不支持、801 | 停止本组件感知，保留原位置与完整功能 |
| 权限缺失或不匹配、201；ACTIVITY_MOTION 授权被拒绝或请求失败 | 记录权限或授权问题，保持原功能与原布局，不重复请求授权 |
| 服务/订阅异常 | 记录 code，撤销跟手增强并回到源基线 |
| 应用明确关闭功能 | 停止感知、忽略迟到回调、清空待移位方向；恢复接入前位置与源基线 |
| 页面隐藏/后台 | 停止感知、忽略迟到回调、清空待移位方向，不更新隐藏页面；缓存页面保留位置状态，再次可见且功能启用时恢复监听 |
| 系统关闭能力 | 核对组件/服务实际行为；有可观察关闭信息时恢复原路径，无公开查询证据时不编造查询接口，不能以无回调推断关闭 |
| UNKNOWN、双手、未握持或暂时无回调 | 保持当前侧，不触发归位或换边动画；尚无有效方向时保持初始位置，不把无回调视为关闭 |

系统原生跟手已启用时，关闭增强可恢复原 `adaptToHandedness` 值；若为接入专门引入 HdsTabs 或悬浮样式，关闭路径须保留原组件树/样式。只关闭一个属性不能证明已恢复原有布局。硬件不支持时系统组件可能保留悬浮样式而不跟手，必须实测并对照基线；无法识别/控制的差异记录为未确认，不能宣称完全回退。

## 回退路径的实测验证

回退行为不能只靠代码复核或构建通过认定。按[验证闭环](../../workflows/verification.md)执行顺序第 7 条：

- 存在低版本兼容分支（工程 compatible API 低于所选路线 minApi）时，必须在 API 低于路线门槛的环境安装本轮构建产物实测：感知不订阅、跟手增强不出现，接入前布局、功能、交互与状态逐项保持，无报错崩溃；采集回退环境运行截图与日志，经 `--import-screenshot` 或 `--manual-evidence` 导入后以 `--judgment` 的 `fallback` 字段（condition 填 `low-api`）补录，summary 写明回退环境与结论。
- 回退实测验证“增强不启用”，不依赖握姿识别硬件，允许使用 API 达标的模拟器；“仅真机”约束只针对跟手/识别效果本身。
- `unsupported`（如系统无智感握姿开关、返回 801）与 `disabled`（页面隐藏、明确关闭）路径同样按能力包触发方式实测后分别补录。
- 无法获得回退环境时报告保留未验证并写明具体阻断；注入异常或模拟状态只证明回退代码分支，不证明真实低版本环境表现，不能据此补录 `passed`。

关闭发生在拖拽/按压过程中时，立即停止新增感知和取消待处理增强，将视觉恢复安排在不打断当前操作的安全时机。保留控制器、索引、文本输入、滚动位置、业务回调与进行中的操作。

暂时无识别结果不等于接口错误。已明确返回的权限、能力、服务或订阅错误仍按表中的错误路径处理，不能用“保持当前侧”掩盖失败。

组合路线互不接管另一个目标。较低版本不自动把握持手改成操作手；需要替代策略时先取得用户明确选择。复核低版本、设备不支持、权限错误、关闭四类路径的组件树、响应式布局、状态、交互和视觉与基线一致。
