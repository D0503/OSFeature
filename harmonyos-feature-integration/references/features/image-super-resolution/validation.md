# 图像超分验证与排障

## 验收

1. 静态验证：用 `verify-integration.mjs --project <工程> --feature image-super-resolution --route core-vision-image-sr` 检查路线和源码候选，再逐调用核对[版本、守卫、业务基线](compatibility-audit.md)及资源关闭。源码候选不等于调用链已证明。
2. 使用 `verify-development.mjs` 构建目标 product；构建通过不代表运行效果通过。正向运行仅用已确认的 `26.0.0+` Phone、Tablet 或 PC/2in1 真机，记录版本、设备形态和 SysCap 结果。用非敏感低清样图，记录实际输入／输出宽高、处理结果、耗时及回收；比较原图与输出的同一区域，不能仅凭像素尺寸证明清晰度。保存属于范围时验证写入目标可重开且原文件未覆盖。
3. 负向验证：取消选图、不可读／非法尺寸、快速重复触发、处理失败、处理中切图或离开后返回，核对不会并发提交、不会回写过期结果、能够继续原流程并可再次操作；用低版本设备实测原流程，或在支持设备走可控的特性关闭分支验证回退，分别标明实际覆盖；关闭分支不能代替低版本实测。检查重复处理后资源有界。
4. 用本轮构建绑定运行日志和可读对照截图。运行通过须补录 `single-image-result`（处理、输入输出尺寸和资源清理）与 `source-state-fallback`（回退场景、原行为、重复触发或过期结果）两项观察并引用日志或组件树。视觉判读展示同一区域的原图和结果，可用一张对照图或两张同条件截图。缺少真机、截图或负向证据时如实标记缺项，不以 Demo 历史证据替代。

## 故障排查

| 现象 | 核对与处置 |
|---|---|
| SDK 无符号或低版本崩溃 | 区分 SDK、compile、target 与运行 API，核对 `@kit.CoreVisionKit` 导入和实际声明；检查初始化、包装调用、清理均未越过版本与 SysCap 守卫。 |
| 401 或输入未执行 | 记录实际解码尺寸、像素格式和输入形态；两边均严格大于 16 且小于 2048，`inputData` 是单个图像对象，不是数组；失效 URI 回到现有选择／错误处理。 |
| 200 超时、繁忙、进程内存飙升 | 从较小且合法的单张图复核；确认进程内门控、大图预解码尺寸、输出保留时间及编解码释放。回收后再允许用户重试，不自动并发重试。 |
| 1018700001 或创建失败 | 查具体报错阶段和原始错误码，再排查真机系统、区域与能力、资源和并发；不能仅以 SysCap 为真判定成功。 |
| 尺寸增长却效果差、白屏或显示旧图 | 核对输入输出绑定、提交顺序、`PixelMap` 是否已释放；用相同区域看边缘与纹理，清晰原图或严重失真的图可能收益有限。 |
| 保存失败或选图取消后原图丢失 | 区分选择、解码、处理、编码、写入阶段，核验授权 URI 和文件关闭；验证原图、旧结果和原业务操作均未被失败路径改写。 |
