# 闪控窗与闪控球场景路由

本映射根据 `/Users/ming/Desktop/projectResource/float-view/docs` 的 2026-09-28 官方文档镜像整理。镜像只用于能力建模和页面定位；开发时仍冻结 `scenarios.json` 登记的华为官网页面，并从本次正文现提版本、权限、设备、尺寸、状态和错误处理判据。

## 先分流

- 只要求跨应用小窗展示或操作：选择闪控窗基础、模板尺寸或生命周期场景（FV-S001～FV-S003）。
- 要求闪控球和闪控窗互相切换：选择 FV-S004。绑定后的点击、启动、停止和回调语义不得套用未绑定模式。
- 只要求闪控球：选择 FV-S005，不为其自动创建闪控窗。
- 要求敏感信息遮挡：选择 FV-S006，并把防窥开关、设备能力和权限作为独立前置条件。
- 明确要求桌面、锁屏、待机屏保连续盯盘：选择 FV-S007。只点名桌面小窗时不得扩张到卡片、Push 或防窥能力。

## 实施边界

- 闪控窗、闪控球、画中画和全局悬浮窗是不同能力。冲突关系、数量限制和设备范围必须从本次冻结正文提取。
- 权限属于运行前置条件。代码应处理未授权、设备不支持和用户拒绝；skill 不得代替用户修改系统开关或授权。
- 尺寸不能只按设计稿写死。需要尺寸适配时，使用本次判据要求的限制查询与变化监听，并以实际矩形回调作为运行证据。
- 注册的状态、尺寸、防窥和销毁监听在控制器失效或业务退出时对称注销；停止失败不能静默丢弃控制器状态。
- 绑定场景必须验证两种形态切换、绑定/解绑、联合停止和绑定态回调差异。独立闪控球的点击行为不能直接作为绑定态预期。
- 全链路盯盘只在用户明确要求时组合多项系统能力；每种形态分别建立判据和证据，不以一张桌面截图代表锁屏或待机验证完成。
