# 文档类型检查表

先选择最主要的一类；混合文档可组合两类检查表。只检查该文档实际承诺覆盖的范围。

## 开发指南 / 接入教程

- 目标能力、适用应用类型、设备和系统范围是否明确；
- 前置条件是否覆盖账号、服务开通、签名、依赖、权限和资源；
- 步骤顺序是否满足依赖关系，是否存在“使用未定义对象”；
- 配置文件、模块层级、键名和示例路径是否准确；
- 代码是否包含精确 import、初始化、核心调用、错误处理和释放；
- 是否给出可观察、可复现的成功标准；
- 关联 API/权限页是否能支持正文中的关键主张。

## API 参考

- 模块名、Kit 导入路径、命名空间和导出类型是否一致；
- API Level、系统能力、设备限制和权限是否完整；
- 参数名称、类型、可选性、默认值和取值范围是否匹配签名；
- callback 与 Promise 重载、同步与异步描述是否混淆；
- 返回值、异常、业务错误码和边界行为是否说明；
- 示例是否使用当前页面描述的签名，而非旧版本写法；
- 相关类型和跳转链接是否有效。

## 配置 / 权限 / 安全说明

- 配置文件和层级是否明确，例如 `module.json5` 与 `AppScope/app.json5`；
- 权限名、授权级别、申请时机、`reason` 与 `usedScene` 是否完整；
- 敏感信息是否被错误建议硬编码；
- 签名、证书、client_id、白名单或控制台步骤是否说明环境差异；
- 拒绝授权、服务未开通、凭据失效等失败路径是否覆盖；
- 示例是否申请了超出功能所需的权限。

## 代码示例 / Codelab 片段

- 代码块是否自包含，缺失部分是否明确标为上下文代码；
- import、变量、类型、函数、资源和配置是否都有来源；
- 生命周期和异步调用顺序是否合理；
- 是否处理异常、空值、权限拒绝、重复调用和资源释放；
- 示例是否能在声明的 SDK/API Level 构建；
- 为简化教学而省略的生产要求是否明确提示。

## FAQ / 故障排查 / 错误码

- 症状、适用版本、根因与解决步骤是否一一对应；
- 一个错误码的多个根因是否被错误合并为唯一结论；
- 排查顺序是否从低风险、可观察步骤开始；
- 建议是否可能破坏数据、降低安全性或掩盖根因；
- 成功判据和回滚方式是否明确；
- 链接到的命令、配置和 API 是否仍适用于目标版本。

## 版本说明 / 迁移指南

- 旧版、新版和生效 API Level 是否明确；
- breaking change、废弃、替代 API 和迁移步骤是否配套；
- 行为变化、默认值变化与配置变化是否区分；
- 是否说明兼容范围、回滚限制和多版本共存策略；
- 示例是否展示迁移前后，而不是只给最终片段；
- 与当前 API 参考和 SDK 声明是否一致。
