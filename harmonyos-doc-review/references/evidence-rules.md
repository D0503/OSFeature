# 证据与核验规则

## 证据层级

针对目标版本，优先级从高到低为：

1. **本机目标 SDK 声明**：对应 API Level 的 `.d.ts`、`.d.ets`、Kit 导出和系统配置 schema；最适合核对签名与可用级别。
2. **同版本官方 API 参考**：参数、返回值、错误码、权限和起始版本；可来自官网抓取，或版本信息已对齐的 `devecocli` 本地官方文档。
3. **目标文档自身及关联官方指南**：适合核对流程、前置条件和场景限制。
4. **官方版本说明、迁移指南与官方示例**：适合解释版本变化和完整调用链。
5. **可复现验证结果**：构建、静态检查、真机或模拟器结果；必须同时记录环境。
6. **第三方资料或模型知识**：只能提供搜索线索，不能单独支持“官网错误”的结论。

证据优先级不是机械的“高者总赢”。例如 API 参考说明签名，本机旧 SDK 不含该 API，可能表示版本不匹配；先对齐 API Level 和更新时间。通过官网与 `devecocli` 读取到同一 documentId 的内容只算一个来源，不能因为访问通道不同而虚增为两条独立证据。

## 最小证据链

每个事实性 finding 至少包含：

- 目标文档定位：章节、表格行、步骤号、API 名或短摘录；
- 被检验的明确主张；
- 一个独立对照来源，或可复现的验证结果；
- 来源版本、API Level 或抓取日期；
- 证据如何支持或反驳目标主张的解释。

只有文档内部矛盾时，同一页面的两个不同位置可以构成证据链，但必须同时引用两个位置。

## 状态判定

| 状态 | 使用条件 |
|---|---|
| `confirmed` | 同版本直接证据明确冲突，或内部两个明确陈述互相排斥 |
| `likely` | 多条官方线索高度一致，但缺少目标版本的最终验证 |
| `ambiguous` | 原文存在两种合理解释，问题是歧义而非已证实技术错误 |
| `version_caveat` | 差异主要由 API Level、SDK、设备或页面更新时间造成 |
| `editorial` | 结构、术语、可读性或信息架构建议，不改变技术事实 |
| `pending` | 缺少正文、版本、关联页、SDK 或运行条件，当前无法判断 |

## 官方交叉核验

1. 从目标文档的 `links` 中优先找 API 参考、权限、开发准备和版本说明。
2. 搜索时带上精确 API/类型名和 HarmonyOS，优先打开 `developer.huawei.com` 原始页面。
3. 核对导入路径、命名空间、方法签名、参数可选性、Promise/callback 形态、错误码、权限和起始 API Level。
4. 对页面显示的更新时间与内容声明的版本分别记录；更新时间新不等于适用版本高。
5. 搜不到对照来源时写“未找到同版本官方证据”，不要写“官方没有说明”。

使用 `devecocli` 时完整遵循 [DevEco CLI 文档核验基线](deveco-cli-baseline.md)。本地索引无结果只表示当前索引未命中，不能证明官网不存在相关说明。

## 本机 SDK 核验

用户提供 SDK 路径或当前工程环境可发现 SDK 时，使用精确 API 名搜索 `.d.ts`、`.d.ets` 和 `@kit` 导出。报告引用应包含：SDK 版本/API Level、绝对文件路径、类型或成员名以及行号。找不到 API 可能意味着搜索范围错误、Kit 未安装或版本过低，需排除后再判错。

## 构建与运行证据

只有用户要求或已提供隔离验证工程时才运行样例。不要把未经确认的片段写入用户业务工程。记录 DevEco/SDK/API Level、设备类型、构建命令和关键错误。模拟器差异不能自动推导真机行为。

## 引用纪律

- 用链接加章节定位，或本地路径加行号；
- 只保留证明问题所需的短摘录，不大段复制页面或代码；
- 明确区分“目标文档称”“对照来源称”“据此推断”；
- 第三方来源要标为辅助线索；
- 抓取日期用于说明证据快照，不把当前页面内容假定为永久稳定。
