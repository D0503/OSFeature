# 闪控球／窗排障

先记录发生错误的具体接口、`BusinessError.code`、`BusinessError.message` 及当时的控制器状态。按实际调用区分独立闪控球、独立闪控窗和窗球绑定，再核对对应检查项。

## 共通错误与现象

| 错误码或现象 | 检查与处理 |
| --- | --- |
| `201` 权限失败 | 在实际宿主的 `module.json5` 和签名 profile 中核对权限声明、ACL 获准情况。球检查 `ohos.permission.USE_FLOAT_BALL`，窗检查 `ohos.permission.FLOAT_VIEW`、`reason` 资源及运行时用户授权。绑定需同时核对两端。 |
| `801` 不支持 | 依次核对实际运行 API、设备及窗口模式、`SystemCapability.Window.SessionManager` 和 `isFloatViewEnabled()`／`isFloatingBallEnabled()` 的结果。使用 Tablet 时核对是否处于电脑模式以及目标系统对该模式的支持。 |
| `1300033` 或启动冲突 | 核对应用是否在前台、是否已启动同应用的窗或球，以及是否已有画中画。独立窗启动前，先等待冲突实例实际停止。 |
| 启动或停止请求返回后，显示状态仍未变化 | 分别等待 `STARTED` 或 `STOPPED` 状态通知。Promise 完成只表示请求完成。 |
| 重复收到回调，或准备／启动失败后仍有监听 | 核对监听是否重复注册。重试前处理本次实例留下的监听，停止后配对退订状态、限制和矩形监听，并清理业务订阅。 |

## 闪控球错误码

| 错误码 | 检查与处理 |
| --- | --- |
| `1300019` | 核对球模板、非空标题、标题和内容各自的 UTF-8 字节数、`PixelMap` 的像素字节数、颜色格式及增强参数的适用版本与前置条件。 |
| `1300021`／`1300022` | 检查同一应用是否尝试创建或启动多个球，或重复调用同一操作。将创建、启动等操作串行执行。 |
| `1300024`／`1300025` | 检查控制器和球是否处于当前接口要求的状态，例如是否在停止后仍调用更新。 |
| `1300026` | 恢复主窗口时，核对触发是否来自用户点击、目标 `Want` 的真实包名与 Ability，以及该操作所需的额外权限。结合 `restoreMainWindow` 的调用结果判断恢复是否成功。 |
| `1300027`／`1300028` | 检查更新参数是否更改了启动时的 `template`，或者是否对 `STATIC` 模板发起更新。 |
| `1300034`（API 26 及以上） | 检查是否与已有闪控窗冲突。独立接入时先结束冲突实例，需要窗球切换时使用绑定流程。 |

## 闪控窗排查

| 错误码或现象 | 检查与处理 |
| --- | --- |
| `1300016`、空窗或页面加载失败 | 对照具体报错接口，核对实际宿主的页面注册、页面资源、加载方式及参数。页面加载成功后再启动。尺寸参数使用 px，并满足当前模板的尺寸和比例限制。 |
| 实际尺寸与请求值不符 | 对照 `onRectChange` 返回的实际矩形及当前模板的尺寸和比例限制。应用设计尺寸使用 vp 时，先转换成 px 再传给窗口接口。 |
| 顶部内容被遮挡或模板切换后留白异常 | 检查根容器顶部预留是否随模板更新。采用常规态 `ROUNDED_RECTANGLE` 预留 32vp、mini 态 `HORIZONTAL_BAR` 预留 4vp 的布局时，确认预留与当前模板同步，并核对 `avoidArea` 的实际值。 |
| mini 态内容贴底或被裁剪 | 比较请求高度与 `onRectChange` 返回的实际高度，并检查 UI 树中的上下留白。系统可能收窄窗口高度，固定行高贴顶会导致裁剪。让内容行高度随内容变化，并通过根容器的 `justifyContent(FlexAlign.Center)` 垂直居中。 |
| 屏幕尺寸变化后窗尺寸未更新 | 工程已有断点或尺寸响应机制时，核对该机制是否触发了重算、vp 到 px 转换及当前模板限制校验。采用固定创建尺寸时，保持该布局策略即可。 |
| 恢复主窗口失败 | 核对是否由用户点击触发、窗是否处于 `STARTED`、主窗口生命周期是否允许恢复，以及 `wantParameters` 类型是否正确。以 `restoreMainWindow` 的调用结果为准。 |

## 窗球绑定排查

| 现象 | 检查与处理 |
| --- | --- |
| 绑定被拒绝 | 确认两端已创建但均未启动，窗页面与尺寸已准备完成。检查是否残留独立实例，或重复点击导致并发创建、绑定或启动。 |
| 切换后形态或引用异常 | 绑定成功后只启动首次展示的一端。切换由系统处理，窗进入 `IN_FLOATING_BALL` 时仍保留当前控制器引用。 |
| 解绑被拒绝或关闭后重建失败 | 已发起启动时，分别确认窗和球均已收到 `STOPPED`，再按需解绑或释放旧组。停止请求的 Promise 完成以及单端停止都不足以确认双端终态。 |
