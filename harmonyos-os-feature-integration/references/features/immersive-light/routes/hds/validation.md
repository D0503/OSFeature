# HDS 路线验证与排障

先执行[共享验证](../../shared/validation.md)，再覆盖本路线矩阵。

## 悬浮 Tab 与导航矩阵

- 手机、平板/折叠展开态和大窗口；竖屏、横屏、分屏与自由窗口；
- 旧工程大断点侧栏行为，确认高版本采用统一底部悬浮还是保留侧栏分支；
- 56vp 显示态及存在隐藏能力时的 0vp 状态，检查跳动和残留点击区域；
- 有/无导航指示区时的 `barBottomMargin`、祖先 bottom padding 和安全区；外层已承担同一间距时 `barBottomMargin` 为 0；
- `barOverlap(true)` 下首尾内容、透明背景、内容 padding 和 `expandSafeArea(BOTTOM)`；
- 所有可滚动 Tab 的最后一项与完整点击热区能越过悬浮栏；检查 `contentEndOffset`、尾部占位或等价 padding；
- 默认栏宽及自定义 small/medium/large 宽度下的多语言、字体放大和页签数量；
- `adaptToHandedness` 的左右偏移、回中和不支持设备表现；
- MiniBar 展开/折叠、Builder 状态、快捷操作、裁剪与背景；API 23 分支不得包含 `barLayoutMode`，API 24+ 分别验证两种布局。

当 `compatibleSdkVersion < 23` 时，API 23 以下设备逐项对照接入前源程序：断点、横竖屏、窗口模式、栏宽栏高、分割线、控制器、页签顺序、自定义 TabBar、隐藏、刷新和滚动范围都保持一致。

## 常见问题

| 现象 | 检查 | 处理 |
|---|---|---|
| HDS 效果过重或卡顿 | 自定义档位、设备支持类型、材质面积 | 改用 `ADAPTIVE`/`SMOOTH`，缩小区域 |
| Web 内嵌控件透明 | API 23 同层渲染 | 关闭控件光感或同层渲染 |
| 悬浮栏离底部过高或出现双重留白 | 祖先 bottom padding 与正数 `barBottomMargin` 是否叠加 | 若祖先已移动整个 HdsTabs，margin 设为 0 |
| 最后一项可见但无法完整点击，或被悬浮栏遮挡 | 每个滚动 Tab 的尾部空间 | 在最后一项后增加足够的 offset/占位/padding |
| 平板侧边导航消失 | 大断点策略是否确认 | 由产品决定统一底部或保留高版本侧栏；旧版保持源体验 |
| 栏宽或文字异常 | 是否沿用旧侧栏宽度、字体倍率和多语言 | 优先系统宽度，定制时验证窗口矩阵 |
| 隐藏后仍占位 | `barHeight`、视觉位移和点击区域是否同步 | 同步布局高度、动画状态和热区 |

## HDS 验收

- 材质接口与 HDS 组件基线没有混淆；
- 悬浮栏位置、间距、滚动遮挡、大断点和 MiniBar 已完成目标矩阵验证；
- API 23 以下普通 `Tabs` 与接入前源程序逐项一致；
- 设备能力和自定义材质档位按规则处理；
- 静态检查、真实构建和待真机项分别报告。
