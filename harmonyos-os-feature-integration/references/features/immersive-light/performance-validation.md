# 沉浸光感性能、降级与验证

## 设备与系统自适应

| 能力 | 高/中算力 | 低算力 |
|---|---|---|
| 材质滤镜、模糊和高光 | 支持 | 降级为背景色、边框和阴影 |
| 材质厚度完整差异 | 支持 | 表现不完整 |
| `colorInvert` | 支持，但受厚度和颜色资源限制 | 不支持 |
| `lightEffect` | 支持 | 不支持 |
| `interactive` | 支持 | 使用降级效果 |
| Dialog/Menu 自动空间动效 | 有条件支持 | 不支持 |

空间动效主要作用于 Dialog 和菜单弹出过程：高算力设备在系统设置“强”或“均衡”时生效；中算力设备仅在“强”时生效；低算力设备不支持。深浅色由系统材质自动适配，不需要创建两套材质对象。

## 降级要求

本节遵循通用 `fallbackPolicy`：所有回退条件都以接入前源程序状态为基线。普通背景、边框或阴影只是视觉保留项；组件树、布局、状态、数据、交互、生命周期以及拒绝/异常路径也必须按实际改造范围保持一致。

- API 低于 23 时不接入当前两条路线，保留普通视觉样式。
- API 23～25 只使用 HDS 支持范围，不引用 API 26 `uiMaterial`。
- API 26 设备不支持沉浸式材质时，保留普通背景色、边框和必要阴影。
- HDS 不支持 `IMMERSIVE` 类型时使用 `SMOOTH`，或回到普通组件样式。
- Web 同层渲染出现组件透明时，关闭对应控件光感或关闭同层渲染。
- 用户或应用级状态禁用材质时，界面仍需可读、可操作，不把材质作为表达业务状态的唯一手段。

## 性能红线

1. 不给整页或超大背景设置材质，把材质限制在卡片、工具栏、悬浮按钮等局部区域。
2. 不在父子节点重复嵌套材质，不给大量 `ListItem` 分别设置材质。
3. 不叠加 `backgroundBlurStyle`、`backgroundEffect` 等重复模糊计算。
4. 不把材质覆盖在视频、动图等持续变化内容上。
5. 避免持续修改材质区域尺寸、位置、透明度、参数或子树结构。
6. 避免对材质区域执行无限循环动画。
7. Dialog 和 Menu 使用空间动效时控制尺寸，避免接近全屏。
8. 不在大量文本和图标的整棵子树上开启自动反色。
9. 需要自定义阴影时关闭材质自带阴影，避免重复绘制。

## 测试矩阵

至少覆盖：

- API 23 和 API 26；需要兼容更低版本时增加最低支持版本回归；
- 高、中、低算力设备；
- 系统沉浸光感“强、均衡、弱”三档；
- 深色模式和浅色模式；
- HDS 标题栏、底部页签以及实际使用的 ArkUI 组件、菜单和弹窗；
- 材质支持与不支持两种能力判断结果；
- 应用级 `default`、`enable`、`disable` 状态；
- Web 同层渲染、动态背景、滚动列表、弹窗和持续动画场景；
- 旧版本和不支持设备的普通视觉降级。

悬浮 Tab 还必须覆盖：

- 手机、平板/折叠展开态和大窗口；竖屏、横屏、分屏与自由窗口；
- 旧工程原本的大断点侧栏行为，确认最终选择是统一底部悬浮还是保留侧栏分支；
- 56vp 显示态以及存在隐藏能力时的 0vp 状态，确认内容没有跳动或残留点击区域；
- 底部导航指示区存在与不存在两种情况，验证 `barBottomMargin`、安全区和内容可点击区域；
- `barOverlap(true)` 下首尾内容是否被遮挡，分别验证有无 `expandSafeArea(BOTTOM)`、内容 padding 和透明背景的实际方案；
- 默认系统栏宽以及自定义 small/medium/large 宽度，确认多语言、字体放大和页签数量变化后不截断；
- `adaptToHandedness` 开启后的左右偏移、回中行为和不支持设备表现；若工程自行监听手势，再单独验证权限与生命周期注销。

当 `compatibleSdkVersion < 23` 时，另建低版本回归矩阵：在 API 23 以下设备逐项对照接入前源程序，确认手机底部栏、平板/大窗口侧边栏、横竖屏切换、分屏/自由窗口、栏宽栏高、分割线、页签顺序、控制器跳转、自定义 TabBar、隐藏和刷新行为均保持一致。高版本 HDS 分支采用统一底部悬浮，不代表低版本普通 `Tabs` 也应改成统一底部。

## 常见问题排查

| 现象 | 优先检查 | 处理方向 |
|---|---|---|
| 材质完全不生效 | API、Stage 模型、module 类型、`MaterialState.DISABLE`、设备支持 | 对齐前置条件；使用能力判断；保留降级样式 |
| 设置了材质但视觉无变化 | 是否同时设置了不透明背景色或背景模糊；材质视觉层级在其下 | 背景改透明或移除背景模糊，让材质层可见；参见 [implementation.md](implementation.md) 材质视觉层级与遮挡 |
| 自绘制组件（TextArea 等）材质被遮盖 | `backgroundColor` 作用于内容层、材质作用于背板层，内容层在上 | 不对这类组件同时使用材质和背景色；不期待材质绘制在内容层 |
| 材质渲染区域与可视区域不一致 | 材质区域由布局区域决定（Checkbox 圆形可视区域得到矩形材质、Text 无法只给文本内容设材质） | 用 `width`、`height`、`borderRadius` 对齐布局区域与预期可视区域 |
| 薄材质边框呈现周围背景颜色 | `ULTRA_THIN`/`THIN` 的折射属正常光学表现 | 接受或改用较厚样式；用带透明度的 `materialColor` 降低折射可见度 |
| HDS 效果过重或卡顿 | 自定义档位、设备支持类型、材质面积 | 改用 `ADAPTIVE` 或 `SMOOTH`，缩小材质区域 |
| Web 内嵌控件透明 | SDK 版本和同层渲染 | 关闭该控件光感或关闭同层渲染 |
| 显式关闭后又出现 | 是否传入 `undefined`、应用是否为 `ENABLE` | 使用 `uiMaterial.Material.empty` |
| 阴影、边框或背景异常 | 属性设置顺序、`applyShadow`、重复模糊与阴影 | 明确最终优先级并移除重复视觉属性 |
| 自动反色无效 | 材质厚度、颜色是否为受支持资源、系统强度、设备算力 | 使用薄材质和受支持颜色资源，验证设备限制 |
| 低性能设备没有流光 | 设备算力和材质支持能力 | 接受系统降级，不把流光作为关键交互反馈 |
| 悬浮栏遮挡列表末项 | `barOverlap`、内容 bottom padding、安全区和栏底部间距 | 根据页面布局增加内容留白或安全区扩展；不要机械复制其他工程的写法 |
| 平板导航从侧边变到底部后效率下降 | 大断点策略是否未经确认、页签数量和内容层级 | 高版本按产品决定统一底部或保留侧栏；低版本分支继续保留源程序原有侧栏行为 |
| 页签胶囊过宽、过窄或文字截断 | 是否沿用了旧 `barWidth`、字体倍率、多语言和窗口宽度 | 优先系统宽度；确需定制时使用悬浮样式的分档宽度并完成窗口矩阵验证 |
| 隐藏后仍占位或可点击 | `barHeight` 是否同步为 0、translate/opacity 是否只改了视觉 | 同步布局高度、动画状态和点击区域并回归快速滚动 |

## 验收标准

- 已记录实际 API、模型、module 和设备上下文；
- 选用接口与版本矩阵一致，没有在 API 23～25 路径引用 API 26 接口；
- API 26 路径包含版本和设备能力判断；
- 不支持设备、旧版本和禁用状态仍有可读可用的普通样式；
- 没有大面积、嵌套、动态背景或无限动画等明显性能风险；
- 悬浮 Tab 的位置、栏高、栏宽、底部间距、内容遮挡和大断点策略已在目标窗口矩阵验证；
- API 23 以下普通 `Tabs` 分支已与接入前源程序逐项对照，原有断点、横竖屏、窗口模式和交互行为保持一致；
- 已执行项目可用的静态检查和构建；
- 真机未覆盖的系统档位、设备算力和视觉结果明确列为待验证，不用编译结果代替效果结论。
