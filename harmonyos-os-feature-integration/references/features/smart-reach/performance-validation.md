# 性能、运行与验收

先执行 `verify-integration.mjs --project <path> --feature smart-reach --route <route> --sdk <path>`。auto 只验证已识别的启用路线；没有入口时明确指定路线并复核。三条组合路线分别调用 `verify-development.mjs`，复用 changes、构建、安装、导航、截图和判定流程，汇总为一份报告。

## 静态与构建

- 本机 SDK、compile、compatible、Stage 主模块和实际新增接口门槛一致；不误用 target 或组件早期 since 降低门槛。
- 权限按所属 HAP 和运行 API 核对；无关模块的权限、注释、测试代码不作为满足证据。库或别名封装未解析时人工沿依赖链核验。
- 原生属性的归属/版本、手动事件的生命周期、同一回调实例与授权流程须复核；源文本候选不能证明控制流。
- 未启用/仅 false、仅 off、未检测到封装不能报告完成。warn 项按本轮文件证据复核，不批量改成通过。
- 使用目标工程实际 SDK 构建；本包的静态夹具和示例检查不等于 ArkTS 编译通过。

## 运行与视觉矩阵

| 场景 | 观察与证据 |
|---|---|
| 支持真机左/右切换 | 确认动作信号与 UI 变化对应，记录事件、日志和目标页面截图；原生与自定义分别验证 |
| 未识别、双手、未握持、重复同值 | 不无故跳边、无重复动画，初始原位置与有效方向保持策略一致 |
| 按压、长按、拖动中换手 | 目标不逃离，原操作不中断，结束后只应用最新有效方向 |
| 页面切换、遮挡、后台、重复进入 | 无重复订阅、隐藏后不更新 UI、不误删其他组件监听 |
| API 低版本、权限拒绝、201/801、服务失败 | 完整保留原业务与布局；注入异常只证明回退逻辑，不证明硬件表现 |
| 应用关闭、系统关闭、订阅/退订失败 | 无循环重试或强制授权；对照源基线，无公开查询时记录观测边界 |
| 竖/横屏、手机/折叠屏/平板、窗口尺寸变化 | 在支持设备正常握姿下验证，沿用原断点、安全区和滚动布局 |
| 左右移动动画 | 贴边组件绕屏外、等高等边距；组内顺序/间距不变；底部栏不遮末项操作区 |

分别读取 [原生](routes/native-component/validation.md)、[操作手](routes/operating-hand/validation.md)、[握持手](routes/holding-hand/validation.md) 的触发条件。操作手需非边缘多次有效触控，握持手需正常接触与亮屏解锁，不能用同一套动作替代验证。

性能比较接入前后的滚动帧率、换手动画、回调次数与隐藏后的监听活动；以项目已有指标验收，不虚构统一阈值。模拟状态可检查代码分支，但不能替代支持设备上的真实握姿识别效果验证。

验收：各所选路线静态问题已处理、构建通过，运行、视觉与回退项分别有依据。缺设备/授权/系统信息时报告保留未验证。截图成功、属性存在或 SysCap 为 true 都不是视觉验证通过。
