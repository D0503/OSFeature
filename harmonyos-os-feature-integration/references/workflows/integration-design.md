# 接入方案工作流

按 [接入方案模板](../../assets/templates/integration-plan.md) 交付。

1. 引用工程发现和可行性门禁结果。
2. 列出全部可选路线与升级选项及各自理由；存在多条路线或需要升级时，先由用户确认路线，再说明未选择路线的原因。
3. 列出依赖、配置、模块、页面和组件改动点，但不编造不存在的文件。
4. 引用实施前源程序状态基线和能力包 `fallbackPolicy`，设计旧版本、不支持设备、未授权、系统禁用和异常场景的分支；这些分支保留原状态，只在增强分支引入新特性。
5. 加入性能、安全、隐私与发布影响；不适用时写明证据范围，而不是省略。
6. 给出静态检查、构建、真机测试矩阵和“接入前/回退分支”逐项对照计划。

用户只要求设计时在此停止，不修改工程。
