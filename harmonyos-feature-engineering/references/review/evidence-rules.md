# 证据与确认规则

## 事实来源边界

可用于确认外部技术事实的来源仅包括：

- 同版本 HarmonyOS API 参考。
- 官方专题、开发指南或变更说明。
- 官方 SDK / 类型声明 / 头文件。
- 官方示例及其明确的版本配置。
- 可复现构建、模拟器或真机结果。

模型记忆、搜索摘要、第三方文章和未标明版本的转述只能帮助发现线索，不能单独支撑 `confirmed`。本地抓取文件即使声称来自官网，也必须通过清单来源字段、正文哈希或重新抓取来确认来源身份；来源身份仍不等于内容正确。

## 证据优先级

针对每个技术主张按以下顺序取证：

1. 与主张直接对应的 API 参考和版本标注。
2. 官方开发指南中的条件、限制和示例。
3. SDK 声明、官方示例工程或发布说明。
4. 可复现的编译结果。
5. 模拟器结果。
6. 真机结果。

后续层级不自动覆盖前一层级。例如编译成功只能说明当前工程和 SDK 接受代码，不能单独证明真机视觉行为。

## 最小证据链

- 外部技术事实的 `confirmed` finding 至少引用一个非目标文档证据：`official_api`、`official_guide`、`sdk`、`build`、`simulator` 或 `device`。
- 内部矛盾的 `confirmed` finding 至少引用两个独立的 `target` / `internal` 位置，并将 `claimScope` 标为 `internal_consistency`。
- 每条证据必须有稳定 ID、来源、定位、支持的主张、版本、抓取时间和 SHA-256；确实未知的字段使用 `null`。
- 链接存在、标题相似或页面可访问不等于证据支持主张。

## 定向抓取预算

默认最多抓取 12 个官方证据页面。按风险排序：会导致错误 API 使用、安全问题、无法编译或全局行为变化的主张优先。

- 只抓取与明确主张相关的官方页面。
- 每次重定向后重新验证 HTTPS、官方域名、端口和凭据限制。
- 不递归遍历全部外链、导航页或站点地图。
- 预算耗尽后，将剩余主张写入 `pendingVerifications`，说明需要的具体证据。

## SDK 与 DevEco 证据

SDK 或工程可用时，按 [DevEco 基线](deveco-cli-baseline.md) 识别本机工具。构建前记录 SDK/API、产品、模块、构建模式和命令。没有隔离工程时，不得为了审查而修改用户工程。

## 代码证据

- 静态检查结果使用 `target` / `internal` 证据，不能伪装为构建结果。
- 构建日志只截取足以定位结果的片段，不在报告中泄露令牌、用户名或无关绝对路径。
- 模拟器和真机结果分开记录设备、系统版本、步骤和可观察结果。
- 失败也可以成为证据，但必须区分文档问题、环境问题和未决原因。

## 引用方式

本地文档使用绝对路径、章节和行号；URL 使用规范 URL、章节锚点或可复现定位。建议保留不超过必要长度的原文摘录，并通过 `sha256` 固定被审查正文。
